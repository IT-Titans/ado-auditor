# v1.3.0

## What's Changed

- Upgraded to .NET 10 and pinned the SDK with `global.json`; .NET 9 is out of security support
- Added rate limiting for the public endpoints, counted per ten minutes: by default 5 audit starts, 3 contact or feedback mails and 300 requests of any kind. A rejected request answers 429 with `Retry-After`, which now reaches the browser
- Prepared rate limits per visitor instead of per frontend server: the frontend passes the visitor address to the backend, which trusts it only with a shared secret. **This is inactive until `NUXT_PROXY_KEY` and `RATELIMITING__TRUSTEDPROXYKEY` are set.** Until then all visitors share one budget
- **Temporary:** images built from `main`, which are the ones deployed to production, run with raised limits of 60 audit starts, 20 mails and 3000 requests per ten minutes (`backend/src/AdoExport.Api/appsettings.branch.main.json`). They are sized for all visitors together, because that is how the budget is shared while the two keys are missing. Remove the file's `RateLimiting` section once the keys are set; per visitor these values are far too generous. The dev environment keeps the defaults
- Added settings per source branch: the pipeline tells the backend image which branch it is built from, and the application loads `appsettings.branch.<branch>.json` when it exists. A setting on the App Service still overrides it
- Added a redirect to the canonical host and to https, switched off unless `NUXT_SHOULD_REDIRECT` is set
- Replaced AutoMapper with Mapperly
- Added a section hinting at the source code to the landing page
- Corrected the spelling of the company name to the one entered in the commercial register, and the owner, the address and the register court in the imprint
- Moved the tests out of the image builds into a Test stage of the pipeline, with published results and coverage
- Added a required minimum of 90 % line coverage for the backend, for the total and for every assembly, and of 90 % for the frontend logic
- Added type check and lint of the frontend to the Test stage
- Pull requests are now validated by the pipeline before they can be merged

## What's fixed

- Fixed starting an audit, sending a contact inquiry and sending feedback without a record of the user's consent: storing consent reported success whatever happened to the mail that is the record
- Fixed confirming a contact inquiry or feedback that could not be sent
- Fixed losing a failed audit metrics or error report mail without a trace; it is logged now
- Fixed the reports endpoint answering 406 instead of 400 or 410
- Fixed every report download being named `.pdf`
- Fixed the rating of an SSH key whose lifetime spans a daylight saving time change
- Fixed the user page failing for a token whose owner cannot be resolved
- Fixed the error page failing for a status code it has no text for
- Fixed the report export failing when the response holds no file
